# T7 — Security hardening (2026-10-09)

> Test counts and target counts in this file are as of T7; the review rounds (R1–R3) added tests and targets afterwards, see `make test` and `make help` for the current numbers.

Threat model and control map: `docs/architecture/security.md` (15 controls, each with its proof).

## Repository guards (`tests/repo/`, part of `make check`)
- `no-owner-literal.test.ts`: no owner name, alias, calendar domain, workspace or host name in `src/`, `scripts/`, Dockerfile, compose files, Makefile. Three cosmetic hits found and removed (a doc comment, a French example in the parse prompt, the Makefile help text).
- `no-llm-tools.test.ts`: no `tools`, `functions`, `tool_choice` in `src/llm` or `src/pipeline`; only `src/llm/deepseek.ts` calls the model.
- `calcom-allowlist.test.ts` (T3): GET only, one fetch call, four paths.
- `slack-scopes.test.ts` (T6): exactly the seven bot scopes and two events, no user scopes.
- `deployment-hardening.test.ts`: compose keeps read-only rootfs, cap drop, no-new-privileges, limits, log rotation, healthcheck, non-root, no wildcard publish, no host networking; image non-root with production dependencies only and no `.env` copied; `.gitignore` and `.dockerignore` cover `.env`, data, backups.

## Integration guards
- `pipeline.test.ts`: over 100 varied questions, every Cal.com request is a GET to an allowlisted path; busy-times is among them.
- `slack.test.ts`: a forged `Host` / `X-Forwarded-Host` on the install route does not change the redirect URI (it comes from configuration); a forged callback state is a 400 page.
- `admin.test.ts` (T5): lockout after five failures, CSRF, cookie flags, escaping, security headers.
- `pipeline.test.ts` (T4): container-style logger receives no question text.

## Live (running container)
- `tests/live/container.test.ts`: `docker inspect` → user `node`, `ReadonlyRootfs true`, `CapDrop [ALL]`, `no-new-privileges:true`, memory and pid limits, `unless-stopped`; published addresses only loopback and the Tailscale IP; a sandbox question with a canary marker leaves no trace in `docker logs` while the structured `question answered` event is present.
- `tests/live/sandbox-http.test.ts`: twelve injection prompts (instruction override, key and prompt exfiltration, delete/book, control tokens, JSON smuggling, impossible time, shell command, "list users") through the real admin sandbox endpoint of the container: every reply a fixed reply or a plain availability answer, no forbidden word.
- `make security-check`: secrets scan clean, `npm audit --audit-level=high` 0 vulnerabilities.

`make check`: 105 passed (105) hermetic tests, scan clean, audit clean, docs-check clean.

Pass criteria of testing plan §5 T7: every control of action plan §6 maps to a green test or live evidence; residual risks documented in the security document.
