# T6 — Slack integration (2026-10-09)

> Test counts and target counts in this file are as of T6; the review rounds (R1–R3) added tests and targets afterwards, see `make test` and `make help` for the current numbers.

## Hermetic (`tests/integration/slack.test.ts`, 11 tests; `tests/repo/slack-scopes.test.ts`, 1 test)
- Manifest: one name for app, bot and slash command; exactly the allowlisted bot scopes and the two events; Socket Mode and the Messages tab enabled; redirect URL only in multi mode; no user scopes.
- Installation store: token encrypted at rest (raw row has no `xoxb`), fetch returns a v2 bot installation, unknown team and org-wide installs refused, delete works.
- `authorize`: the right token per team, never another workspace's; unknown team and org-wide refused.
- Seeding from `SLACK_BOT_TOKEN`: stored once via `auth.test` with the scope list; an existing row is never overwritten by a newer env token; missing team id refused.
- Handlers with synthetic payloads and fakes: DM answered with the asker's zone/locale/name from `users.info`; bot messages, edits and channel messages ignored; mention answered in a thread under the message or in the existing thread; slash command acknowledged first with an ephemeral placeholder then replaced by the ephemeral answer; a pipeline failure becomes the cannot-check reply in the asker's language; a failing `users.info` degrades to the owner zone.
- Install routes: multi mode needs a session, redirects to `https://slack.com/oauth/v2/authorize` with client id, the allowlisted scopes, the configured redirect URI and a state; a forged callback is a 400 "Install failed" page; single mode has no install routes (404).
- Scope guard: the scope list equals the scope document's allowlist.
